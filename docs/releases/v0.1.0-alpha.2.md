The second alpha of **Dogubako** (道具箱, "toolbox"), 249 small tools for your
files in one app. This release fixes problems found by testing alpha.1 on
Linux and makes self-hosting easier on Podman and arm64.

This is an alpha for testers. Things will break, and settings or file formats
may change before 1.0. Please [report problems](https://github.com/Mischa-dev/Dogubako/issues).

## Opening the app

Open the DMG and drag Dogubako to Applications.

<!-- Variant B: unsigned. Keep this if there was no Developer ID at release time. -->
This alpha is not signed with an Apple Developer ID yet, so macOS blocks it the
first time:

1. Open the DMG and drag Dogubako to Applications.
2. Open Dogubako. macOS says it can't verify the developer. Click **Done**.
3. Open **System Settings → Privacy & Security**, scroll to the message about
   Dogubako and click **Open Anyway**, then confirm with your password.

You only need to do this once. If you opened alpha.1 this way, you need to do
it again for alpha.2.

## What's new

### Self-hosting

- **Podman.** The compose file now works under Podman with SELinux
  enforcing, keeps its health check, and there's a Quadlet unit
  (`deploy/dogubako.container`) that starts Dogubako at boot with the same
  hardening as the compose file. See
  [Podman](https://docs.dogubako.app/self-hosting/podman/).
- **arm64 builds.** The Docker image now builds on arm64 hosts (such as a
  Raspberry Pi 5 or an Ampere server). The published image is still
  linux/amd64 only.
- **Background removal in the image.** Build with `DOGUBAKO_WITH_REMBG=1` in
  `.env` to include rembg. Once you download a model in **Settings → Models**,
  Remove Background works offline.
- **Clearer missing-engine hints.** In the Docker image, **Settings →
  Dependencies** tells you which `.env` option adds a missing engine (for
  example `DOGUBAKO_WITH_OFFICE=1`) instead of suggesting `apt install`.
- **Tailscale.** The install guide no longer lets `tailscale serve` take over a
  service that already uses HTTPS port 443 on the same machine.

### Fixes from Linux testing

- **Linux CLI starts on current distros.** alpha.1's Linux binary needed
  glibc 2.43 and failed on Debian 13. It now needs glibc 2.28 or newer. (#31)
- **Speaker-labelled transcription.** The `whisper-small.en-tdrz` model
  downloads again; alpha.1 got a 404. (#30)
- **Detect Faces / Blur Faces.** A threshold of 0 is rejected with a message
  instead of crashing the tool. The minimum is now 0.1. (#32)

### Release and licenses

- The engine sources tar is built from the exact upstream source each engine
  was built from, and every download is checked against its pinned checksum or
  git commit.

## Privacy

Unchanged from alpha.1. With the desktop app, your files are processed on your
Mac and never uploaded. With a hosted Dogubako, they go to that server. There
is no telemetry and no account for desktop use. Network tools, model and engine
downloads, and plain-words mode only use the network when you ask.

## Known issues

- **Apple silicon only** for the desktop app. Managed engines come from
  Homebrew, which no longer builds for Intel Macs.
- **No Linux desktop package.** You can build it from source; see
  [Build](https://docs.dogubako.app/develop/building/).
- **Some tools need engines the app doesn't manage yet:** LibreOffice (Office
  conversions), Piper (text to speech) and rembg (background removal). Install
  them yourself; **Settings → Dependencies** shows what's missing and how.
- **ExifTool** uses the Perl that ships with macOS.
- The CLI binaries don't include engines; they use what's installed on the
  system (`dogubako deps` lists what's missing).
- Remove Background in the Docker image, with a model that isn't downloaded
  and no network, fails with a Python `ConnectionError` instead of pointing
  to **Settings → Models**.
