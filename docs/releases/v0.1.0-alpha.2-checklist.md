version bump are ready on this branch. Nothing has been tagged, published or

## 3. Draft (automatic, after the merge)

- [ ] The **Release** run on main is green and a draft `v0.1.0-alpha.2`
      exists. A fix merged after this: Actions › Release › Run workflow on
      main, which replaces the draft.
- [ ] The draft has every asset: DMG, engine packs + `packs.json`, three CLIs,
      `engine-sources-0.1.0-alpha.2.tar`, `SHA256SUMS.txt`, and its body is the
      notes below their `---` line.

## 4. Ship (Mischa only)

1. Check the draft on the releases page:
   - [ ] The DMG opens on a clean Mac, and an on-demand engine downloads (try OCR).
   - [ ] The Linux CLI from the draft runs `--help` on Debian 13
         (`docker run --rm -v "$PWD:/b" debian:13-slim /b/dogubako-x86_64-unknown-linux-gnu --help`).
2. Actions › **Ship release** › Run workflow with `0.1.0-alpha.2`. It verifies
   the draft and `SHA256SUMS.txt`, pushes `ghcr.io/mischa-dev/dogubako:0.1.0-alpha.2`,
   publishes the release (which creates tag `v0.1.0-alpha.2` at the draft's
   commit) and deploys dogubako.app and docs.dogubako.app. Until then the docs
   site keeps the alpha.1 pages, even though `site/` on main says alpha.2.
3. Mark the milestone done in the workspace and announce.

## Rollback

- Bad release: mark it as a pre-release or delete it, re-run **Website** by
  hand with `v0.1.0-alpha.1`, and ship the fix as `0.1.0-alpha.3`. A published
  tag is never moved.
- Bad website deploy: Cloudflare Pages → dogubako-website → Deployments →
  roll back to the previous one.
