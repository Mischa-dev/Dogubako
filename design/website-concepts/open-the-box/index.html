道具箱·dōgu-bako, “toolbox”

249 tools for your files, in one box.

Dogubako replaces the single-purpose websites you use to convert an image, shrink a PDF or format some JSON. It runs on your computer, or on a server you host, so your files stay with you. Free and open source.

One job, start to finish

Drop a file. Get it back.

A 4.2 MB photo that needs to be smaller, done in the app without uploading it anywhere.

It lands on your bench.

Drag a file onto the window, or pick it from the big input on the home screen. Dogubako draws it as what it is: a photo as a print, a PDF as a stack of pages.

It asks what should happen.

The likeliest tools for that file come up numbered 1 to 4. Type “smaller” and Compress Images moves to the top.

Press Run.

Settings sit beside the preview, and the work happens on your own computer. Ctrl Enter runs it too.

The same job, four ways

One tool, four ways in.

The Compress Images you just watched is also a command, an HTTP endpoint and a tool your AI agent can call.

On the command line.

dogubako <category> <tool>, with the same options as the form. Pipes work too.

Over HTTP.

Upload a file once, get an id back, and run any tool against it from your own scripts and services.

From an AI agent.

In compact mode the MCP server lists a handful of meta-tools instead of all 249. The agent searches for the right one, then runs it.

Described once.

Each tool is described once. The form, the command, the HTTP call and the MCP call are generated from that description and run by the same engine, so they always agree.

Local-first

Nothing leaves your machine.

Most converters start with an upload. Dogubako doesn’t have one.

Not even to be converted.

The work happens where the file already is. No upload, no queue, and no server of ours in the loop.

It stays in the box.

The desktop app needs no account and sends nothing anywhere. Host it yourself and your files only travel to a machine you own.

your machine
the internet 0 B uploaded
stays here

What “local” means here.

Account
None for the desktop app. A shared server has accounts, and every file is checked against its owner on every request.
Telemetry
None. No analytics, no crash reporter, no usage pings.
Shell
Never used. External programs run directly, with timeouts, resource limits and optional bubblewrap sandboxing.
Archives
Guarded against zip bombs and path tricks before anything is written.
Network tools
On a shared server, tools that fetch URLs refuse to reach into your private network by default, and every action goes to an audit log.
License
GNU AGPL v3.0 or later. The code is all there to read.

Self-hosting and agents

Host it once. Give each agent its own key.

Run Dogubako on a home server, a NAS or a VPS with the heavy engines installed once, then open it from any browser on your network, phones included. Each agent gets a scoped token, and a token only opens the drawers it was given.

image-bot can open 1 of 12 drawers: Images, without OCR.

# on the server
$ docker compose up -d --build
$ docker compose logs dogubako | grep "Setup token"

# one account per agent, limited to its tools
$ dogubako users create media-bot --role agent \
    --allow 'video.*' --allow 'speech.*' --allow 'audio.*'
$ dogubako tokens create --user media-bot --name laptop

# or run it locally for Claude Code
$ claude mcp add dogubako -- \
    dogubako mcp serve --discovery compact
